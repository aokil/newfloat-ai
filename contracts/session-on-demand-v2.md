# 单会话与按需校验 v2

2026-10-18：用户确认取消闲置常驻通知并要求修改，覆盖 v1 的在线SSE即时退出要求。本轮仅源码实现，未构建、执行测试、操作设备、推送或部署；生产仍须更新配套后台/网页和Android后才能按本协议验收。

## 1. 单会话规则保持

- 每个账户只保留一个有效登录会话。新一次成功登录在原有事务中撤销旧会话、创建新会话；失败登录不撤销当前会话。
- refresh维持同一sessionId、一次性轮换凭据，不创建新登录；重放撤销原家族，已撤销会话不能refresh恢复。
- 每个受保护业务请求仍检查数据库会话、账户禁用、访问凭据期限及该业务的权限/点数。移除通知不取消这些检查，也不允许只凭客户端“已登录”放行。
- 改密、找回密码、显式退出、管理员强退/封禁继续写入原有会话撤销状态，无需数据库迁移。

## 2. 客户端按需联网

- Android恢复本机登录、留在前台闲置、退后台、网络恢复均不创建会话通知流、心跳、重连任务或账户轮询。
- 网页登录后不订阅通知；窗口保持打开、隐藏/显示、网络恢复也不主动连接通知或刷新账户。
- AI、支付、登录、显式账号操作、反馈提交及公告/推广读取等实际业务仍使用原有一次性请求；访问凭据只在业务需要时按原规则刷新并安全重试。
- 受保护请求明确返回SESSION_REVOKED、ACCOUNT_DISABLED或明确的会话到期/重放失效时，客户端按当前身份归属清除登录。并发刷新期间旧凭据返回的错误不得清除已轮换的新凭据；网页重试后的明确失效也须清除当前会话。
- 不可安全重试的变更请求不自动重放。支付待处理查询只在已有支付流程内按原生命周期运行，不新增后台轮询。

## 3. 失效提示与本地能力

- 新登录提交后，旧会话的服务端权限立即失效；旧客户端不再靠持续通知立即切换界面，而是在下一次受保护请求/按需refresh发现失效并退出。
- 本机题库、OCR等继续使用原本的缓存授权和正可用点数门槛，期限不因本次修改延长；本地余额仍只是缓存，在线AI/支付以服务端账本为准。
- 没有任何通信时，不宣称客户端能够即时知道服务器撤销状态。此次用户接受的取舍是停止闲置通知、延后到实际联网操作获知失效。

## 4. 旧通知接口退役

`GET /v1/auth/session-events` 返回立即结束的JSON错误：

```json
{"error":{"code":"SESSION_EVENTS_DISABLED","message":"会话通知已停用，请更新应用；登录状态会在联网操作时校验","retryable":false}}
```

- HTTP 404，Cache-Control: no-store；不hijack响应、不返回text/event-stream、不检查/续期通知用特殊过期token、不创建订阅或心跳。
- 后台不再初始化通知事件总线或专用PostgreSQL LISTEN连接，也不发送pg_notify；真实会话撤销数据库写入保持。
- 旧Android/网页收到404后原实现仍会约每5分钟重试一次。后台退役可以阻止其900秒长请求，但不能远程删除旧客户端内的重试逻辑。需要更新Android、刷新已打开网页；新版不再调用此接口。

## 5. 退出与边界

- Coze HTTP服务关闭时先拒绝新请求、停止监听并关闭空闲连接，给已接收业务请求最多30秒排空，再关闭后台/数据库；45秒总退出上限处理异常悬挂，SIGTERM/SIGINT重复触发不重复关闭。
- 模型测试与AI预留点数的既有数据库过期恢复任务仍保留，避免资金状态失去清理；它们不是客户端常驻HTTP订阅，不把此次修改描述成“服务器没有任何后台工作”。
- 取消闲置通知不等于项目所有托管费用归零。实际业务请求、其他用户/网页访问和旧客户端请求仍可能产生用量；节省比例须上线后对齐实际CU用量与账单验证。
