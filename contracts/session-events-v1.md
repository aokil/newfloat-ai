# 单账户唯一登录会话与撤销通知 v1

2026-10-04：仅源码实现，未构建、运行测试、连接设备或部署。上线需同时更新后台、Android 与网页；源码完成不代表公网已实行。

## 登录规则

- 每个账户同时只保留一个有效登录会话，Android 和网页共同遵守。
- 用户名/密码验证成功并在事务内复核账户可用后，撤销该用户全部旧会话并创建新会话。密码输错或登录事务失败不会撤销旧会话。
- SQLite 使用现有 `BEGIN IMMEDIATE`，PostgreSQL 使用现有跨实例写事务锁；并发成功登录按提交顺序覆盖，最后一次保留。
- 同一会话正常 refresh 只轮换凭据，保持 sessionId，不创建新登录，不撤销自身；已经撤销的会话无法 refresh 复活。
- 不采集硬件标识。不同浏览器、重新提交登录、App 与网页分别登录均属于不同会话，即使在同一物理设备。
- 退出仅清会话和内存凭据，原账户本机题库文件保留。

## GET /v1/auth/session-events

请求通过 HTTPS 的 `Authorization: Bearer …` 传递当前保存的访问凭据；凭据不进入 URL 或日志。

这是严格限权的通知端点：对 Bearer 作格式和 SHA-256 哈希验证，并精确匹配数据库中当前 `sessions.access_hash`；同时验证未撤销、用户未禁用且 `refresh_expires` 未到期。它不读取客户端提供的 sessionId/claims 来信任身份。

为保持业务鉴权按需进行，通知端点允许最近签发、仍匹配存储哈希的访问凭据已超过 15 分钟业务有效期。该例外只用于本会话撤销通知，不返回账户/余额/题库数据，不修改服务器状态，不更新 Android 离线期限，也不调用或扩展 refresh。所有普通 API 与 refresh 的现有到期、撤销和鉴权规则保持原样。

成功响应 `text/event-stream`、`Cache-Control: no-store, no-transform`，事件如下：

```text
event: ready
data: {"sessionId":"当前会话ID"}

event: revoked
data: {"sessionId":"当前会话ID","code":"SESSION_REVOKED"}

```

禁用账户使用 `ACCOUNT_DISABLED`。每 20 秒发送 `: keepalive` 注释维持连接，不查数据库或完整账户。每条通知限小消息，不携带昵称、点数、题目、令牌或其他会话资料。连接最长持续 24 小时且不超过 refresh 有效期，然后重新建立通知连接。

客户端仅对已验证连接上的自身 sessionId 撤销事件或明确的撤销/禁用/refresh 到期错误清除登录。连接失败、超时、404、503、格式异常不算撤销。客户端以 1–60 秒退避重连；未部署端点的 404/405 退避 5 分钟。恢复网络后立即尝试连接。与业务 refresh 并发时等待正在进行的凭据轮换再判断旧凭据的 401，避免自己换 token 时误退出。

## 事件传递与边界

- SQLite：撤销事务成功提交后在进程内通知；回滚及回滚的嵌套保存点不会发出撤销通知。
- PostgreSQL：在撤销事务内调用 `pg_notify`，提交后跨实例推送；独立 `LISTEN` 连接按 schema 和用户分发。只在事件发生时检查订阅会话的撤销/禁用状态。
- 建立订阅先注册监听再重新验证，封闭“认证后、监听前发生撤销”的窗口。
- PostgreSQL 监听掉线时关闭 SSE 流并退避恢复；客户端重连重新验证。监听不可用返回 503，不伪造撤销或继续宣称通知正常。
- 连接每账户最多 4 条，单实例活动流最多 4096；慢读连接超过缓冲限制关闭，避免无限堆积。
- 新登录、退出、改密、找回密码、刷新令牌重放、后台网页撤销/禁用都会触发通知。独立 SQLite CLI/人工数据库写入不经过进程事件，旧客户端在下一次鉴权或重新订阅时失效。
- 离线设备、已被系统结束的 App、被系统暂停的网页或受代理限制的长连接无法保证即时收到事件；恢复进程/网络、通知连接或受保护操作时重新校验。未经真机、公网代理和多实例验证，不声明“实测即时退出”。
