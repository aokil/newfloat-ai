# 预览模型选择失败定位

日期：2026-10-01。用户反馈已 Pull 后，预览中模型选择仍失败。

## 已确认的原因

前端 `workspace.js:getCatalog()` 首先请求 `/v1/models/catalog`；读取失败时停在错误及重试页，尚未访问 Coze SDK。DEV 静态脚本已经与 GitHub bb145b2 原字节一致，但所有业务 API 仍由网关转给既有独立账号／题库后台，Pull 不启动或更新该后台。

本轮通过预览同源地址做只读检查，未携带用户凭据、未登录或调用生成模型：

| 路径 | 返回 | 含义 |
| --- | --- | --- |
| `/v1/models/catalog` | 404，Fastify 默认 `error` 字符串 | 配套新目录接口未上线 |
| `/v1/admin/coze-models` | 404，同上 | 新管理员真实元数据入口未上线 |
| `/v1/admin/models` | 401，`INVALID_CREDENTIALS` | 既有接口存在且正常要求登录 |
| `/health` | 200，ok | 原后台在线；最近已确认仍 schema5 |

浏览器标签状态读取 30 秒后超时，未获取或修改登录凭据，没有声称完成界面截图或模型调用验收。

## 代码反馈修复

0.5.2/schema8 候选保持既有模型业务和计点协议，仅补模型接口缺失的明确失败原因、Coze 未就绪说明与持久重试状态。未添加静态假型号或假可用状态，重试不能替代后台升级。

- `app.js` 只将两个确定的模型目录路径的 HTTP 404 映射为 `MODEL_SERVICE_NOT_DEPLOYED`，明确显示“当前后台尚未提供模型目录，配套模型服务还未上线”。其他接口沿原错误处理。
- `workspace.js` 在模型选择／自带 Key 页保留错误说明和重试入口，读取失败清掉旧目录缓存。搜题页原地重读目录、保留题目输入，失败状态不会再被覆盖为“正在读取”。
- 两个修改的 JS 文件 `node --check` 均通过；未新增或运行测试，未进行模型生成或真实计费。布局、图标、计点协议和 APK 本轮未改。
- 已生成独立 `question-bank/artifacts/m8.1/question-bank-server-0.5.2-model-feedback.zip`，342,571 字节，SHA-256 `498AD259DFD75DCBCDD621AB194A50B2261237DDB8986A891BE1749B0469E53C`；0.5.1 历史包保持冻结。源码同步结果另记。
