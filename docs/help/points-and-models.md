# 点数与模型

## 点数有什么用？

可用点数大于 0 时，可以启动悬浮窗、导入题库等基础功能。余额为 0 时，这些功能暂不可用。

使用基础功能本身不扣点。只有调用平台提供的内置模型时，才会消耗相应点数；在本地题库中找到答案，不消耗点数。

## 内置模型如何扣点？

按每次模型调用计算，调用前需有足够的可用点数。

| 模型 | 每次调用 |
| --- | --- |
| 豆包 Mini、豆包 Lite | 1 点 |
| Qwen 3.5 Plus | 1 点 |
| MiniMax M2.5、MiniMax M2.7 | 1 点 |
| GLM 4.7 | 1 点 |
| GLM 5.0、GLM 5-Turbo | 2 点 |
| 豆包 2.1 Pro | 2 点 |

例如，剩余 1 点时，仍可使用基础功能，也可调用 1 点模型；调用 2 点模型则需要至少 2 点。

## 自己接入的模型会扣点吗？

使用自己的 API Key 接入 DeepSeek 或其他自定义模型，不消耗平台点数。

自接入模型也遵守基础功能的使用门槛：平台可用点数仍需大于 0。余额为 0 时，即使已填写自己的 API Key，也不能启动悬浮窗或导入题库。

## 在哪里查看？

在“我的”查看可用点数；在搜题页的模型选择中切换内置模型，或添加自己的模型。

Android v41 与网站 0.5.1 本地候选已接入上述规则；实际可用型号由已部署服务的管理员配置决定。内置模型先预占、成功回答后扣点，失败释放；网络中断后可找回已完成的回答，不重复扣点。上线与设备状态以 `docs/CURRENT_STATE.md` 为准。

内置模型可由 Coze 项目集成提供，无需普通用户填写供应商 Key。实际名称以模型选择页为准；例如不同实际版本的豆包 Pro 使用 2 点档，不能把显示槽位名称当作平台版本。Coze 平台资源与本产品点数分开核算，平台集成未配置或真实检查未通过时模型不可用。自带 Key 仍通过供应商官方接口使用。
